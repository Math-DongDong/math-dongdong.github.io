## 5. RTDB 규칙 배포 (4개)

각 데이터베이스마다 콘솔에서 따로 붙여넣어야 합니다.
Firebase 콘솔 → Realtime Database → 상단에서 **DB를 선택** → 규칙.

| 순서 | 파일 | 콘솔에서 고를 데이터베이스 |
|---|---|---|
| 1 | `rules/rtdb-1-relativefrequency-가위바위보.txt` | relativefrequency |
| 2 | `rules/rtdb-2-gridgomoku-오목.txt` | gridgomoku |
| 3 | `rules/rtdb-3-blottogame-블로토.txt` | blottogame |
| 4 | `rules/rtdb-4-sentimentanalysis-감성분석.txt` | sentimentanalysis |

각 파일을 열어 **전체 선택 → 복사**한 뒤, 규칙 탭의 내용을 **전부 지우고** 붙여넣으세요.

> 파일 맨 위의 `//` 로 시작하는 줄들은 설명 주석입니다. RTDB 규칙 편집기는
> `//` 주석을 지원하므로 그대로 붙여넣어도 됩니다.
> 혹시 편집기가 거부하면 `//` 로 시작하는 줄만 지우고 다시 붙여넣으세요.
>
> **DB를 잘못 고르면 다른 게임이 멈춥니다.** 붙여넣기 전에 콘솔 상단의
> 데이터베이스 이름이 표의 것과 같은지 꼭 확인하세요.

## 7. 학생 기기로 확인

| 확인 항목 | 기대 결과 |
|---|---|
| 빠른 입장 방 입장 | 방 코드만으로 즉시 시작 |
| 게스트 체크 후 빠른 입장 방 | 체크와 무관하게 똑같이 즉시 시작 |
| 인증 모드 방 첫 입장 | 학교·선생님·학번·PIN 입력 → 입장 |
| 인증 모드 방 두 번째 입장 | 아무것도 묻지 않고 "내 정보가 맞나요?" → 입장 |
| 게스트 체크 후 인증 모드 방 | 정보를 새로 입력 → 선생님 승인 대기 → 승인 시 입장 |
| 같은 방에 두 기기 입장 | 서로 다른 닉네임 |
| 교사 대시보드 방 목록·학번 표시 | 정상 |

여섯 게임을 각각 한 번씩 돌려보고, F12 콘솔에 `permission_denied`가 0건인지 확인하세요.

# 게임별 입장 방식 정리

활동 성격에 따라 필요한 것만 켜 두었습니다.

| 활동 | 빠른 입장 | 학생 인증 | 게스트 승인 | PIN 초기화 | 학번 표시 |
|---|---|---|---|---|---|
| 정수와 유리수 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 곱셈과 나눗셈 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 좀비헌터 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 가위바위보 | ✅ | ✅ | ✅ | ✅ | ✅ (표 + 의견) |
| 좌표평면 오목 | ✅ | — | — | — | — |
| 블로토 | ✅ | — | — | — | — |
| 텍스트 감성 분석 | ✅ | — | — | — | — |

오목·블로토·감성 분석은 **학생 정보를 쓰지 않는 활동**이라 빠른 입장만 남겼습니다.
방을 만들 때 모드를 묻지 않고, 대시보드에 PIN 초기화 버튼과 학번 토글이 없으며,
입장 화면에도 게스트 체크박스가 없습니다.

**빠른 입장 모드**에서는 게스트 체크박스를 켜든 끄든 결과가 같습니다. 방 코드만으로 바로 시작합니다.

**학생 인증 모드**는 처음 한 번만 학교·담당 선생님·학번·PIN을 입력받고,
그 뒤부터는 이 기기에 저장된 정보로 조용히 확인만 하고 들어갑니다.
저장되는 것은 PIN이 아니라 되돌릴 수 없는 증명값입니다.

**가위바위보**는 대전이 실시간이라 진행 데이터는 RTDB에 두고,
인증에 필요한 것(방 모드·닉네임 이름표·게스트 승인·학번)만 Firestore
`rps_records` 에 얹었습니다.
**방을 만들 때 두 DB에 함께 쓰고, 지울 때 두 DB에서 함께 지웁니다.**

**오목·블로토**는 인증이 없지만 Firestore를 한 가지 용도로만 씁니다 — 닉네임 중복 방지
(`gomoku_records` / `blotto_records` 아래 `nicknames`).
필드가 없는 빈 문서라 잃을 정보가 없습니다.

**감성 분석**은 Firestore를 전혀 쓰지 않습니다.

새 컬렉션들은 보안 규칙의 `.*_records` 패턴에 이미 걸리므로 규칙은 그대로 두시면 됩니다.

**게스트 모드**는 인증 모드 방에서만 동작합니다.
이 기기에 저장된 정보를 한 줄도 쓰지 않고 새로 입력받으며,
이미 접속 중인 학번이면 막고, PIN이 맞아야 하고, 선생님이 승인해야 들어갑니다.
닉네임도 폰 주인 것을 물려받지 않고 새로 뽑습니다.

# 남아 있는 한계

학생에게 로그인이 없으므로 아래는 규칙만으로 막을 수 없습니다.
수업 진행에는 지장이 없는 수준이라 그대로 두었습니다.

1. 콘솔에서 다른 닉네임의 기록을 덮어쓰는 것
2. 자기 점수나 승수를 직접 올리는 것 (값의 범위는 제한했습니다)
3. 아직 등록하지 않은 학번의 PIN을 남이 먼저 만들어 두는 것
   → 선생님이 **학생 관리 → PIN 초기화**로 풀어주시면 됩니다
4. 남이 쓸 닉네임을 미리 차지하는 것

근본 해결책은 Firebase 익명 인증입니다. 학생 화면에는 아무 변화가 없고
(`signInAnonymously` 한 줄 + 규칙 수정), 지금 구조 위에 나중에 얹을 수 있습니다.
