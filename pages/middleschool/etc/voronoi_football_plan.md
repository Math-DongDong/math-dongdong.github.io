> - **방향**: 전술판(정지 분석) + 경기 시뮬레이션을 균형 있게 제공

## 0. 한눈에 보기

- Apps Script·구글 시트·Tailwind를 걷어내고 **Bootstrap 5 단일 HTML**로 옮긴다. (CLAUDE.md 규칙: 흰 배경, 시맨틱 태그, 공통 navbar)
- 픽셀 칠하기 보로노이 → **수직이등분선으로 자른 진짜 다각형**. 선수별 넓이(㎡)를 신발끈 공식으로 정확히 계산한다.
- "델로네 패스망"이라 부르던 *200px 이내 연결선* → **진짜 델로네 삼각분할**(보로노이 이웃 관계)로 교체한다.
- 화면을 **전술판 모드**와 **경기 모드** 두 개로 나눈다.
- 경기 AI가 보로노이 정보를 실제로 쓰도록 바꾼다. (빈 공간 = 넓은 셀, 패스 후보 = 델로네 이웃, 공간 찾기 = 셀 무게중심)

### 3.5 포메이션 프리셋

- 블루 시점(오른쪽 공격)으로 정규화 좌표 `fx, fy ∈ [0, 1]`를 정의한다. **`fy = 1`(화면 아래)이 블루의 오른쪽**이다.
- 레드는 **180° 회전**: `x' = 105 − x`, `y' = 68 − y`. 이렇게 하면 레드의 RB도 레드 기준 오른쪽(화면 위)에 자동으로 놓인다. (B9 해결)
- 프리셋: `4-4-2`, `4-3-3`, `4-2-3-1`, `3-5-2`, `3-4-3`, `5-3-2`
- 팀별 전술 슬라이더
  - **라인 높이** 0~20m: GK를 뺀 필드 플레이어 전체를 앞으로 이동
  - **폭** 70~120%: 터치라인 방향으로 벌리거나 좁히기
  - **간격** 70~110%: 수비~공격 라인 사이 세로 간격 압축

```js
function slotToWorld(slot, team, tactic) {
  let x = slot.fx * FIELD.L;
  let y = FIELD.W / 2 + (slot.fy - 0.5) * FIELD.W * tactic.width;
  if (slot.role !== 'GK') {
    x = 18 + (x - 18) * tactic.compact + tactic.lineHeight; // 18m 지점을 기준으로 세로 압축
  }
  x = clamp(x, 1, FIELD.L - 1); y = clamp(y, 1, FIELD.W - 1);
  return team === 'blue' ? { x, y } : { x: FIELD.L - x, y: FIELD.W - y };
}
```

## 4. 보로노이 다각형 엔진 (핵심)

### 4.1 원리

선수 P의 지배 영역 = **경기장 직사각형** ∩ (다른 모든 선수 Q에 대해 "Q보다 P에 더 가까운 쪽" 반평면)

각 반평면의 경계선이 바로 **선분 PQ의 수직이등분선**이다. 반평면은 볼록하므로 결과 셀도 항상 볼록다각형이다.

### 4.2 알고리즘: 반평면 클리핑

경기장 직사각형에서 시작해 수직이등분선으로 21번 잘라낸다. 자를 때 새로 생긴 변에 "어느 선수 때문에 생긴 변인지" 표시해 두면, 나중에 델로네 이웃을 공짜로 얻는다.

```js
// 반평면 { v | (v − M)·n ≤ 0 } 만 남기기 (Sutherland–Hodgman 한 단계)
function clipByBisector(poly, p, q, qId) {
  const mx = (p.x + q.x) / 2, my = (p.y + q.y) / 2; // 중점 M
  const nx = q.x - p.x,       ny = q.y - p.y;       // 법선 n = P→Q
  const side = v => (v.x - mx) * nx + (v.y - my) * ny; // ≤ 0 이면 P 쪽
  const out = [];
  for (let i = 0; i < poly.length; i++) {
    const a = poly[i], b = poly[(i + 1) % poly.length];
    const da = side(a), db = side(b);
    if (da <= 0) out.push(a);
    if ((da <= 0) !== (db <= 0)) {
      const t = da / (da - db);
      const I = { x: a.x + (b.x - a.x) * t, y: a.y + (b.y - a.y) * t };
      // 나가는 교점: 다음 변은 수직이등분선 위(qId) / 들어오는 교점: 원래 변 유지
      out.push({ ...I, edge: da <= 0 ? qId : a.edge });
    }
  }
  return out;
}

    { x: FIELD.L, y: 0,       edge: 'right' },
    { x: FIELD.L, y: FIELD.W, edge: 'bottom' },
    { x: 0,       y: FIELD.W, edge: 'left' }
  ];
  return sites.map(p => {
    let poly = rect;
    for (const q of sites) {
      if (q === p) continue;
      poly = clipByBisector(poly, p.pos, q.pos, q.id);
      if (poly.length === 0) break;
    }
    const neighbors = new Set(poly.map(v => v.edge).filter(e => !WALLS.has(e)));
    return { playerId: p.id, poly, area: polygonArea(poly), centroid: polygonCentroid(poly), neighbors };
  });
}
```

- **같은 자리 보호**: 두 선수 거리가 0.01m 미만이면 법선이 0이 되므로, 드래그를 놓을 때 0.05m 밀어낸다.
- **계산량**: 22명 × 21번 × 꼭짓점 ~12개 ≈ 프레임당 5천 번 연산 → 60fps에 여유. (기존 픽셀 방식은 프레임당 240×150×22 ≈ 79만 번)

### 4.3 넓이와 무게중심 (신발끈 공식)

```js
function polygonArea(poly) {
  let s = 0;
  for (let i = 0; i < poly.length; i++) {
    const a = poly[i], b = poly[(i + 1) % poly.length];
    s += a.x * b.y - b.x * a.y;
  }
  return Math.abs(s) / 2;
}

function polygonCentroid(poly) {
  let s = 0, cx = 0, cy = 0;
  for (let i = 0; i < poly.length; i++) {
    const a = poly[i], b = poly[(i + 1) % poly.length];
    const c = a.x * b.y - b.x * a.y;
    s += c; cx += (a.x + b.x) * c; cy += (a.y + b.y) * c;
  }
  return { x: cx / (3 * s), y: cy / (3 * s) };
}
```

- 팀 지배율 = 팀 셀 넓이 합 ÷ 7,140㎡ (105 × 68)
- **검증 불변식**: 22개 셀 넓이 합 = 7,140㎡ (오차 0.1 이하). 개발 중 `console.assert`로 매 프레임 확인한다.
- **구역별 넓이**: 같은 클리핑 함수를 일반 직선용(`clipByLine`)으로 만들어 `x = 35`, `x = 70`으로 자르면 수비 ⅓ / 중원 ⅓ / 공격 ⅓ 넓이가 나온다. 페널티박스 직사각형으로 자르면 "박스 지배율"도 구할 수 있다.

### 4.4 델로네 삼각분할

| 용도 | 계산 방법 |
|---|---|
| 전체 22명 델로네 | 4.2의 `neighbors` 그대로 사용 (보로노이 ↔ 델로네 쌍대 관계) |
| 팀 패스망 | 같은 팀 11명만으로 보로노이를 한 번 더 계산 → 그 이웃 관계 = 팀 델로네 |
| 패스 길 안전도 | 팀 델로네 변(선분)에서 가장 가까운 상대 선수까지 거리 `d`. `d < 2m` 빨강(차단 위험), `2~5m` 노랑, `> 5m` 초록 |

- 경기장 밖에서만 만나는 이웃(외곽 선수끼리)은 빠질 수 있다. 수업에서는 "경기장 안에서의 이웃"이라고 설명한다.
- 기존 `voronoi.html`의 O(n⁴) 외접원 검사 방식은 쓰지 않는다.

## 6. 경기 시뮬레이션 재설계

### 6.1 상태 머신

```text
TACTICS ──▶ KICKOFF ──(1초)──▶ PLAYING ⇄ PAUSED
               ▲                  │ 골 / 경기 종료
               └── GOAL(2초) ◀────┘        └──▶ FULLTIME (결과 모달)

PLAYING 안에서 ball.state: 'held' | 'pass' | 'shot' | 'loose'
```

- GOAL 상태에서는 위치 업데이트를 멈추고 배너만 보여 준다. (B1 해결)
- KICKOFF: 양 팀을 자기 진영 대형으로 배치하고, 실점한 팀 ST에게 공을 센터서클에서 준다. (B2 해결)

### 6.2 루프 (고정 타임스텝)

```js
const STEP = 1 / 60;
let rafId = null, last = 0, acc = 0, simSpeed = 1;

function frame(now) {
  acc += Math.min((now - last) / 1000, 0.1) * simSpeed;
  last = now;
  while (acc >= STEP) { update(STEP); acc -= STEP; }
  render();
  rafId = requestAnimationFrame(frame);
}
function play()  { if (rafId) return; last = performance.now(); rafId = requestAnimationFrame(frame); }
function pause() { cancelAnimationFrame(rafId); rafId = null; }
```

- 모니터 주사율과 상관없이 같은 속도 (B5), 루프 중복 없음 (B6)
- 이동은 항상 최대 속도 제한 함수로만 한다 (B7)

```js
function moveToward(p, target, speed, dt) {
  const dx = target.x - p.pos.x, dy = target.y - p.pos.y, d = Math.hypot(dx, dy);
  if (d < 0.05) return;
  const step = Math.min(d, speed * dt);
  p.pos.x += dx / d * step;
  p.pos.y += dy / d * step;
}
```

### 6.3 팀 행동

**팀 블록 이동 (공 위치 기준)**

```text
shiftX = clamp((ball.x − 52.5) × 0.5, −20, 20)    // 공 따라 앞뒤로
shiftY = (ball.y − 34) × 0.25                      // 공 쪽으로 쏠림
공격팀: 블록 목표 = anchor + shift + 전진 8m, 폭 ×1.1
수비팀: 블록 목표 = anchor + shift,            폭 ×0.85 (좁히기)
```

**공격팀 오프더볼**: `목표 = lerp(블록 목표, 내 셀의 무게중심, 0.3)`
→ 셀 무게중심 쪽으로 움직이면 자연스럽게 빈 공간으로 퍼진다. (로이드 알고리즘 아이디어, 수업 포인트)

**수비팀 역할 분담** (A2 해결)

| 역할 | 누가 | 움직임 |
|---|---|---|
| 1차 압박 | 공에 가장 가까운 필드 플레이어 1명 | 공 소유자에게 접근 (최대 속도) |
| 커버 | 두 번째로 가까운 1명 | 공과 자기 골대 중앙을 잇는 선 위, 공에서 8m 지점 |
| 대형 유지 | 나머지 | 블록 목표 위치 |
| GK | GK | 골라인 위에서 공의 y를 따라가되 골포스트 사이로 제한 |

### 6.4 공 가진 선수의 판단 (0.4초마다)

세 가지 선택지의 점수를 매겨 가장 높은 것을 고른다. 가중치는 모두 `CONFIG.WEIGHTS`로 빼서 조정한다.

**① 패스** — 후보: 팀 델로네 이웃 + 5~35m 안의 전진 패스 후보

```text
score = 1.0 × 전진량(m)
      + 0.05 × 수신자 셀 넓이(㎡)          ← 빈 공간에 있는 동료
      + 2.0 × min(패스 길 안전도(m), 6)    ← 길목에 상대가 없는 패스
      − 0.3 × 패스 거리(m)
```

**② 슈팅** — 골대 중앙까지 25m 이내일 때만

```text
골 확률 = clamp(0.45 − 0.015 × 거리, 0.03, 0.4) × (1 − 슈팅 길 차단율) × 각도 보정
```

**③ 드리블** — 1차 압박자가 4m보다 멀 때 가산점. 방향 = 골대 방향 + 가까운 상대 회피(6m 이내 반발력), 속도 = 최대 속도 × 0.85

### 6.5 판정

| 상황 | 규칙 |
|---|---|
| 패스 | 공 속도 16 m/s, 수신자의 0.5초 뒤 예상 위치로 보냄. 비행 중 상대가 공 1.0m 안에 들어오면 인터셉트 |
| 태클 | 상대가 공 소유자 1.2m 안에 있으면 초당 60% 확률로 소유권 이동 (`확률 × dt`) |
| 슈팅 | 공 속도 25 m/s로 골대 쪽 이동, 도착 시 6.4 확률로 골/선방 결정. 선방이면 GK 소유 |
| 공 아웃 | 경기장 밖으로 나가면 상대 팀 공으로 가장 가까운 경계에서 재개 (스로인·골킥 구분 없이 단순화) |
| 경계 | 모든 선수 `pos`를 경기장 안으로 클램프 (B3 해결) |
| 무작위 | `Math.random` 대신 **시드 난수**(mulberry32) → 같은 시드 + 같은 전술 = 같은 경기 (전술 공정 비교) |

- [ ] 60Hz·120Hz 모니터에서 경기 속도 동일
- [ ] 재생/정지를 연타해도 속도가 빨라지지 않음
- [ ] 골 1번에 GOAL 배너 1번, 스코어 +1
- [ ] 공과 선수가 경기장 밖으로 나가지 않음 (아웃 시 재개)
- [ ] 같은 시드 + 같은 전술 → 같은 경기 결과
- [ ] 모바일에서 캔버스 드래그 시 페이지 스크롤 없음, 가로 스크롤 없음
- [ ] 레티나/태블릿에서 라인·숫자가 선명

## 10. 확장 아이디어 (선택)

- **속도 가중 지배 영역**: "도착 시간 = 거리 ÷ 최대 속도"로 영역을 나누면 경계가 직선이 아니라 **원(아폴로니우스의 원)**이 된다. 다각형으로는 못 그리므로 기존 픽셀 방식을 이 모드에서만 재활용한다. → "속도가 다르면 경계가 왜 휘어질까?" 심화 탐구
- **빠른 시뮬레이션 N경기**: 화면을 그리지 않고 10경기를 빠르게 돌려 전술별 평균 골·지배율·승률 비교
- **리플레이**: 0.1초 간격으로 위치를 기록해 골 장면 되감기
- **지배 히트맵**: 경기 동안 각 지점을 어느 팀이 더 오래 지배했는지 누적 표시
- **오프사이드 라인 표시**: 수비 최종 라인 x좌표에 세로선 표시
