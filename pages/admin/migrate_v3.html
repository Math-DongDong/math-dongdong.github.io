v3 마이그레이션

한 번만 실행하는 페이지입니다. 작업이 끝나면 이 파일을 서버에서 삭제하세요.

실행 순서가 정해져 있습니다
  1. 0번 진단을 먼저 눌러 지금 어떤 규칙이 살아 있는지 확인합니다.
  2. 1번 (평문 PIN 제거) — 규칙 배포 전
  3. Firebase 콘솔에서 Firestore 규칙과 RTDB 규칙 4개를 배포합니다.
  4. 2번 (교사 목록·권한), 3번 (오목 방 보정) — 규칙 배포 후
0. 진단 (먼저 실행)

로그인한 계정의 uid를 보여 주고, Firestore·RTDB에 새 규칙이 적용되었는지 실제 쓰기를 시도해 확인합니다. 아무것도 바꾸지 않습니다. (확인용으로 만든 임시 문서는 즉시 지웁니다)

1. v1 평문 PIN 제거 규칙 배포 전

v1 시절 student_auth 문서에는 PIN이 평문으로 들어 있었습니다. 이 문서는 학생 누구나 학교명_학번으로 읽을 수 있으므로, 남아 있다면 친구의 PIN이 그대로 보이는 상태입니다.
학생들의 PIN은 그대로 쓸 수 있습니다 — 해시(private/auth)는 건드리지 않습니다.

2. 공개 교사 목록 · 실시간 게임 권한 규칙 배포 후

승인된 교사를 teacher_directory(학교·이름만)와 실시간 데이터베이스 4개의 teacher_uids에 등록합니다.
두 경로 모두 새 규칙에만 있습니다. 규칙을 배포하기 전에 누르면 permission-denied가 납니다.

3. 오목 방에 status 넣기 규칙 배포 후

새 규칙에서 학생은 오목 방 노드를 통째로 읽지 못하고 status 한 칸만 봅니다. 이 값이 없는 기존 방은 "존재하지 않는 방"으로 보이므로 채워 둡니다. (새로 만드는 방은 코드가 알아서 넣습니다)
2번을 먼저 실행해야 합니다. 교사 권한 목록이 있어야 쓰기가 통과합니다.
