# 모션 슬라이드 — 수업 활동(의견 모으기 · 슬라이드 꾸미기) 설계

> **상태**: 설계(구현 전) · **작성일**: 2026-11-21 · **대상 파일**: `motionslide.html`(같은 폴더), `js/teacher-auth.js`, Firebase 규칙
>
> 함께 보기([motionslide-live-plan.md](motionslide-live-plan.md)) 위에 얹는 기능입니다. 그 문서에서 빼기로 했던 **의견 모으기(D16)를 이 문서로 다시 엽니다.**
> 코드 위치는 줄 번호가 바뀌므로 **객체·함수 이름**으로 적었습니다. `motionslide.html`에서 이름으로 검색하세요.

## 0. 한눈에 보기 — 일이 진행되는 순서

```
0단계  기반 공사 ─────────── 화면에는 거의 안 보임. 1~3단계가 모두 이 위에 올라감
  │    학생 익명 인증 · 학생이 쓸 수 있는 규칙 · 방 닫을 때 학생 답도 함께 지우기
  ▼
1단계  의견 모으기 ───────── 먼저 수업에서 써 보고 다음으로
  │    교사: 장에 질문 붙이기 → 학생: 답하기(모든 기기) → 교사: 결과 보기(막대·포스트잇·표) → CSV 저장
  ▼
2단계  슬라이드 꾸미기 ────── 글·도형·수식만, 태블릿·PC에서만 편집
  │    교사: 활동 장 지정 → 학생: 장 위에 꾸미기 → 교사: [학생 화면 모아 보기]
  ▼
3단계  사진 ─────────────── 학생이 꾸미기에 사진 넣기(기기에서 줄여서 올림)
```

| 단계 | 교사가 하는 일 | 학생이 하는 일 | 다음 단계로 가는 기준 | 작업량 |
|---|---|---|---|---|
| 0 | 콘솔 설정 몇 가지 | (변화 없음) | 학생 기기에서 자기 칸에만 쓸 수 있고, 기존 게임·설문이 그대로 동작 | 작음 (점검이 중요) |
| 1 | 편집기에서 질문 붙이기, 발표 중 [마감]·[결과] | 휴대폰·태블릿·PC에서 답하기·고치기 | 실제 수업 1회에서 답하기·마감·CSV·방 닫기까지 문제없음 | 중간 |
| 2 | 활동 장 지정, [학생 화면 모아 보기] | 태블릿·PC에서 장 위에 글·도형·수식 넣기 | 실제 수업 1회, 30명 모아 보기가 느리지 않음 | **큼** (터치용 편집기) |
| 3 | (2단계와 같음) | 사진 넣기 | 사진이 들어간 수업 1회, 사용량 확인 | 작음 |

- 각 단계는 **실제 수업에서 한 번 써 본 뒤** 다음 단계로 갑니다. 써 보고 필요 없으면 거기서 멈춰도 됩니다.
- 1단계까지만 해도 수업에서 쓸 수 있는 완성된 기능입니다.

## 1. 정한 것

| 번호 | 결정 | 이유 |
|---|---|---|
| A1 | **학생끼리는 서로의 답·작품을 보지 않음.** 교사만 봄 | 학생끼리 보면 받는 양이 30배가 됨. 부적절한 내용이 반 전체에 퍼지지 않음 |
| A2 | **의견 모으기를 먼저** 만듦 | 데이터가 아주 적고, 글만 받아 안전하고, 휴대폰으로도 답할 수 있고, 수업에서 자주 씀. 여기서 만든 기반(익명 인증·쓰기 규칙·결과 창·정리)을 2·3단계가 그대로 씀 |
| A3 | 질문 유형: **객관식**(하나 / 여러 개 고르기) + **이유**(없음 / 선택 / 필수), **장문형** | 사용자 결정. 단답형은 Q3에서 정함 |
| A4 | **장문형 질문에는 교사가 필요할 때 그림 1장을 붙일 수 있음.** 그림은 덱에 들어가 학생이 덱과 함께 받음 | 문제 그림·자료를 보고 쓰게 하려고. 따로 올리고 받을 곳이 필요 없음(5.1) |
| A5 | **슬라이드 꾸미기는 태블릿·PC에서만 편집**, 휴대폰은 보기만. **의견 답하기는 휴대폰도 됨** | 휴대폰 화면에서 개체를 끌고 고치기는 어려움. 글 입력은 휴대폰도 편함 |
| A6 | 학생이 보내는 것은 **HTML이 아니라 정해진 데이터**(종류·위치·글·색)만 | 교사 PC는 승인 교사로 로그인된 상태. 학생이 조작한 HTML이 교사 PC에서 실행되는 일을 막음 |
| A7 | 학생은 **Firebase 익명 인증**으로 자기 uid를 가짐 | 자기 답만 쓰고 고치게 하는 규칙을 쓰려면 꼭 필요(가이드북 10장 "근본 해결책") |
| A8 | 청중 화면에 결과를 띄울 때는 **이름 숨김이 기본** | 교사 화면에서만 이름이 보임 |
| A9 | 학생 답·작품은 **함께 보기를 취소(방 닫기)할 때 함께 지움.** 그 전에 CSV로 저장하라고 안내 | 학생 이름·학번이 들어 있는 기록이라 오래 남기지 않음 |
| A10 | **학생이 답에 사진을 붙이는 기능(손풀이 사진 등)은 이번 범위 밖** | 필요하면 3단계(사진 줄이기·올리기)가 끝난 뒤 같은 방법으로 검토 |

## 2. 구현 전에 정할 것

| 번호 | 질문 | 추천 |
|---|---|---|
| Q1 | 질문은 언제 열리나? | 교사가 **그 장에 오면 자동으로 열림**, 닫기는 교사가 **[마감]** |
| Q2 | 마감 전에 교사가 다음 장으로 넘어가면? | 학생 화면 아래 **"아직 답하지 않은 질문 1개"** 단추로 계속 답할 수 있음 |
| Q3 | **단답형**도 넣을까? | 넣음. 수학 답 확인(같은 답끼리 묶어 개수)·워드클라우드에 좋음 |
| Q4 | 객관식 **정답**을 지정할까? | 지정은 선택. 결과 화면에서 정답 막대만 색을 다르게. **학생용 덱에서는 정답 칸을 뺌**(덱을 풀어 보면 보이므로) |
| Q5 | **전체 보기(복습) 모드**에서도 답할 수 있나? | 답할 수 없음. 질문과 내 답만 보임 |
| Q6 | 한 화면뿐인 교실(**휴대폰으로 진행**)에서 결과는? | 1단계: 휴대폰에 응답 수와 [마감]만, 결과는 PC 청중 화면 위에 덮어 보이기(휴대폰 [결과] 단추) |

> 빠른 입장 방은 닉네임이 자동으로 붙어 **누가 쓴 답인지 알 수 없습니다.** 이름이 필요한 활동은 학번 인증 방으로 여세요. 시작 창에 이 안내를 한 줄 넣습니다.

## 3. 전체 구조

```
 [교사 PC: 편집기]
   장 ⋯ 메뉴 / 직접 삽입 → [질문 붙이기] → slide.ask (덱에 저장, 장문형 그림 포함)

 [교사 PC: 함께 보기 시작]
   LiveDeck.build → 학생용 덱에 질문 포함(정답 칸은 뺌) → Storage (기존과 같음)

 [교사 PC: 발표자 모드]
   질문 장에 옴      ──► RTDB live/{code}/asks/{askId} = 'open'
   [마감]           ──► RTDB live/{code}/asks/{askId} = 'closed'
   발표자 바 [❓ 12/27] · [결과] 창 ◄── RTDB live_answers/{code}/{askId}/*  (교사만 읽음)
   [청중 화면에 띄우기] → 청중 화면에 결과(이름 숨김)

 [학생 기기] ── 익명 인증(uid) ──
   받아 둔 덱의 질문 + live/{code}/asks 구독 → 열린 질문이면 답 칸
   [제출] / [수정]  ──► RTDB live_answers/{code}/{askId}/{내 uid}   (자기 칸만 쓸 수 있음)
```

- 진행 신호·일시정지·보기 모드는 기존 함께 보기 그대로입니다. 질문은 그 위에 **`asks`(열림/마감)와 `live_answers`(학생 답)** 두 칸만 더합니다.
- 2단계 꾸미기도 **질문 유형 하나(`canvas`)**로 넣어 같은 열기·마감·결과 창을 씁니다.

## 4. 0단계 — 기반 공사

### 4.1 학생 익명 인증
- 학생 보기 화면을 열 때(`LiveView.open`) **`auth.currentUser`가 없을 때만** `signInAnonymously(auth)`를 부릅니다.
- **이미 교사로 로그인된 브라우저**(교사가 학생 화면을 시험할 때)는 그 uid를 그대로 씁니다. 익명 로그인을 하면 교사 로그인이 풀리기 때문입니다.
- 학생 브라우저가 익명 uid를 기억하므로 **새로고침해도 같은 사람**입니다. 자기 답을 다시 불러와 고칠 수 있습니다. 기기나 브라우저를 바꾸면 새 사람이 됩니다.
- 학번 인증 방이면 입장 정보(학번·이름)를 답에 함께 적습니다. 이 값은 학생 기기가 쓰는 값이라 완전히 믿을 수는 없습니다(가이드북 10장의 한계와 같은 수준). 수업 활동에는 충분합니다.

**꼭 고쳐야 할 곳: `js/teacher-auth.js`**
- 지금 `renderNavbarAuth`는 로그인한 사용자에게 `teachers/{uid}` 문서가 없으면 **교사 등록 창(`showRegistrationModal`)**을 띄웁니다.
- 학생이 익명 로그인을 하면 이 창이 학생에게 뜹니다. **`user.isAnonymous`이면 로그아웃 상태처럼** 다루도록 고칩니다(등록 창 없음, 내비게이션은 로그인 단추 그대로, `isApprovedTeacher = false`).
- 익명 학생이 사이트의 다른 페이지로 가도 같은 처리가 적용되는지 확인합니다.

**콘솔**
- Authentication → 로그인 방법 → **익명** 사용 설정.
- 익명 계정은 기기·브라우저마다 하나씩 쌓입니다. 기본 인증은 비용이 없습니다. 프로젝트를 Identity Platform으로 올렸다면 월 활성 사용자 무료 한도 안인지 확인합니다.

**기존 규칙 전수 점검 (0단계에서 가장 중요)**
- 익명 학생도 `auth != null`(Firestore·Storage는 `request.auth != null`)이 됩니다.
- Firestore, RTDB 4개 인스턴스, Storage 규칙 중 **`auth != null`만으로 교사·관리자를 판정하는 곳**이 있으면 익명 학생에게 열립니다.
- 그런 곳은 `teachers/{uid}.status == 'approved'`, `teacher_uids/{uid}`, 관리자 uid 확인으로 바꿉니다. 고친 뒤 Rules Playground로 "익명 사용자" 요청을 시험합니다.

### 4.2 학생 쓰기 규칙 (RTDB 전용 인스턴스 `motionslide-live`에 추가)
```json
"live": {
  "$code": {
    "asks": { ".read": true }
  }
},
"live_answers": {
  "$code": {
    ".read":  "auth != null && (auth.uid === '<ADMIN_UID>' || root.child('live').child($code).child('createdBy').val() === auth.uid)",
    ".write": "auth != null && (auth.uid === '<ADMIN_UID>' || root.child('live').child($code).child('createdBy').val() === auth.uid)",
    "$askId": {
      "$uid": {
        ".read":  "auth != null && auth.uid === $uid",
        ".write": "auth != null && auth.uid === $uid && root.child('live').child($code).child('asks').child($askId).val() === 'open'",
        ".validate": "newData.hasChildren(['name', 'at'])",
        "name":   { ".validate": "newData.isString() && newData.val().length <= 40" },
        "sid":    { ".validate": "newData.isString() && newData.val().length <= 20" },
        "choice": { "$i": { ".validate": "newData.isNumber() && newData.val() >= 0 && newData.val() < 10" } },
        "reason": { ".validate": "newData.isString() && newData.val().length <= 500" },
        "text":   { ".validate": "newData.isString() && newData.val().length <= 2000" },
        "items":  { ".validate": "newData.isString() && newData.val().length <= 20000" },
        "at":     { ".validate": "newData.val() === now" },
        "$other": { ".validate": false }
      }
    }
  }
}
```
- `live`의 `asks`는 기존 `live/$code` 규칙 안에 더합니다(교사 쓰기는 기존 규칙이 허락).
- 학생은 **자기 uid 칸만**, 그리고 **그 질문이 열려 있을 때만** 씁니다. 마감되면 쓰기가 거부됩니다.
- 교사(방 주인)와 관리자는 그 방의 답을 모두 읽고 지웁니다.
- 글자 수 상한으로 큰 데이터를 반복해서 보내는 일을 막습니다. `items`(2단계 꾸미기)는 **JSON 글 하나**로 받아 길이로 크기를 제한합니다(RTDB 규칙은 자식 개수를 셀 수 없어서).

### 4.3 정리
- `Live.cancel`, `Live.closeForDecks`, `js/teacher-cleanup.js`, `room_registry`의 `parts`에 **`live_answers/{code}`**를 더합니다(3단계는 Storage `live_work/{code}/`도).
- 방 닫기 확인 창: "학생 답 N개도 함께 지워집니다. 필요하면 먼저 [결과] 창에서 CSV로 저장하세요."

### 4.4 0단계 끝 기준
- [ ] 학생 기기: 익명 로그인 → 자기 칸 쓰기 성공, **남의 uid 칸 쓰기 거부**, 마감된 질문 쓰기 거부
- [ ] 학생 기기에 교사 등록 창이 뜨지 않음
- [ ] 교사가 같은 브라우저에서 학생 화면을 열어도 교사 로그인이 유지됨
- [ ] 기존 게임·설문·학생 관리·Storage 관리가 그대로 동작

## 5. 1단계 — 의견 모으기

### 5.1 교사: 질문 붙이기 (편집기)
- 썸네일 ⋯ 메뉴(`SlideMenu`)와 직접 삽입 메뉴(`DirectInsert`)에 **[질문 붙이기]** → 질문 창(모달, `MathEditor`와 같은 방식).
- 한 장에 질문 하나. 질문이 있는 장은 썸네일에 **❓** 표시.

```
┌ 질문 붙이기 ──────────────────────────────────┐
│ 유형  (● 객관식) (○ 장문형) (○ 단답형)                │
│ 질문  [ 이 포물선이 아래로 볼록한 이유는?           ]  │
│ ── 객관식 ──                                       │
│ 보기  ① [a > 0]   ② [a < 0]   ③ [      ]  [+ 보기]  │
│ ☐ 여러 개 고르기      이유  (○ 없음)(● 선택)(○ 필수)  │
│ 정답(선택)  [①]   ← 교사 결과 화면에만 보임            │
│ ── 장문형 ──                                       │
│ 그림  [그림 넣기]  ▣ 미리보기  [빼기]                  │
│       (긴 변 1280px로 줄여 저장 — 보통 100~300KB)     │
│ 글자 수 제한  [500]                                 │
│                              [질문 지우기] [취소] [저장] │
└───────────────────────────────────────────┘
```

**데이터 (덱 안, 장마다)**
```js
slide.ask = {
  id: 'q1a2b3',                         // 결과를 묶는 키
  type: 'choice' | 'long' | 'short',    // 2단계에 'canvas' 추가
  text: '질문 글',
  choices: ['a > 0', 'a < 0'],          // 객관식, 최대 10개
  multi: false,                         // 여러 개 고르기
  reason: 'none' | 'optional' | 'required',
  answer: [0],                          // 정답(선택) — 학생용 덱에서는 뺌
  image: 'data:image/jpeg;base64,…',    // 장문형 그림(선택)
  max: 500                              // 장문형 글자 수 제한(최대 2000)
}
```
- **장문형 그림(A4)**: 교사 PC에서 긴 변 1280px, JPEG 품질 0.8로 줄여 덱에 넣습니다. 함께 보기 덱 파일에 들어가 학생이 입장할 때 함께 받습니다. **따로 올리거나 받을 곳이 필요 없습니다.** 덱 크기 검사(30MB)에도 그대로 포함됩니다.
- `Editor.normalizeSlide`가 `ask`를 정리(모르는 칸 버림, 길이 제한)합니다. 되돌리기 기록은 덱 전체를 저장하므로 질문도 자동으로 되돌려집니다.
- `LiveDeck.build`(학생용 덱 만들기)에서 `answer`를 뺍니다.
- 슬라이드 화면에는 질문이 자동으로 그려지지 않습니다. 학생 답 칸 위에 질문 글이 보입니다. 슬라이드에도 보이게 하려면 교사가 글 상자로 적습니다.
- 내보낸 HTML(오프라인)에서는 질문이 무시됩니다.

### 5.2 학생: 답하기 (모든 기기)
```
 휴대폰                              태블릿·PC
┌──────────────┐               ┌──────────────────────┬──────────┐
│  (슬라이드)    │               │                      │ ❓ 질문   │
│              │               │     (슬라이드)         │ 보기 ①②③ │
├──────────────┤               │                      │ 이유 [  ] │
│ ❓ 질문        │ ← 아래에서     │                      │ [제출]    │
│ ① a>0  ② a<0  │   올라오는 판   └──────────────────────┴──────────┘
│ 이유 [       ]│
│     [제출]    │
└──────────────┘
```
- 실시간 페이지에서 질문 장이 열리면(`asks/{id} == 'open'`) 답 칸이 뜹니다.
- **객관식**: 보기 단추 → (설정에 따라) 이유 칸 → [제출]. 마감 전까지는 [수정]으로 바뀝니다.
- **장문형**: 그림(누르면 크게) + 글 칸(남은 글자 수 표시) → [제출].
- **단답형**(Q3): 한 줄 칸(50자) → [제출].
- 마감되면 "마감되었어요"와 내 답만 보입니다.
- 제출 전에 쓰던 글은 기기에 임시로 남겨 둡니다(새로고침해도 유지).
- 일시정지(⏸) 중에는 덮개가 답 칸도 가립니다. 쓰던 글은 그대로 남습니다.
- 학생 글은 화면에 **글자로만** 넣습니다(`textContent`, HTML로 넣지 않음).

### 5.3 교사: 결과 보기
- 발표자 모드에서 질문 장에 오면 발표자 바에 **[❓ 응답 12/27] [마감] [결과]**가 보입니다.
- **[결과]** → 별도 창(청중 화면처럼). 한 화면 교실은 Q6.

| 유형 | 결과 화면 |
|---|---|
| 객관식 | 보기별 **막대그래프**(인원·%) + 아래에 **보기별로 묶은 이유 포스트잇**. 같은 답을 고른 학생들의 이유를 비교해 오개념을 찾기 좋음. 정답을 정했으면 정답 막대만 초록 |
| 장문형 | **포스트잇 ↔ 표** 전환. 포스트잇을 누르면 크게. ★로 골라 두기 |
| 단답형 | 같은 답끼리 묶어 개수 순 + 워드클라우드 |

- **[이름 보기]** 토글: 교사 창에서는 켜짐이 기본. **[청중 화면에 띄우기]** 하면 이름은 꺼진 채로 띄웁니다(A8). 결과 전체 또는 ★ 고른 것만 띄울 수 있습니다.
- **[CSV 저장]**: 이름(닉네임·학번), 고른 보기, 이유, 답, 제출 시각. 엑셀에서 한글이 깨지지 않게 BOM을 붙입니다.
- 교사는 **지금 질문의 `live_answers/{code}/{askId}`만 구독**합니다. 학생이 제출·수정할 때 그 학생 칸만 받습니다.
- **다시 쓸 코드**: [relativefrequency.html](../../middleschool/1/relativefrequency.html)의 의견 포스트잇·학생 현황표·학번 칩 토글·의견 마감 잠금, [textexpression.html](../../aimath/text/textexpression.html)의 워드클라우드.

### 5.4 데이터 구조 (RTDB)
```
live/{code}/asks/{askId}: 'open' | 'closed'          // 교사만 씀, 학생은 읽기
live_answers/{code}/{askId}/{uid}: {
  name:   '김○○' | '자동 닉네임',                      // 입장 정보에서
  sid:    '30312',                                    // 학번 인증 방만
  choice: [1],                                        // 객관식
  reason: '…',                                        // 500자 이하
  text:   '…',                                        // 장문형(설정값, 최대 2000자) · 단답형(50자)
  at:     서버 시각
}
```

### 5.5 사용량 (학생 30명, 질문 5개, 1회씩 고침)
| 항목 | 양 |
|---|---|
| 교사가 받는 답 (RTDB) | 30명 × 5문항 × 약 1KB × 2번 = **약 300KB** |
| 장문형 그림 | 덱에 포함. 200KB × 30명 = 6MB (덱 받기에 포함됨) |

함께 보기 덱을 받는 양(수업당 약 180MB, 설계 문서 8.2)에 비하면 무시할 만합니다.

### 5.6 1단계 범위 밖
- 학생끼리 서로 답 보기(A1)
- 학생이 답에 사진 붙이기(A10)
- 결과를 덱에 저장(CSV로만 보관)
- 내보낸 HTML(오프라인)에서 질문

### 5.7 1단계 끝 기준
- [ ] 실제 수업 1회: 휴대폰·태블릿·PC 모두 답하기·수정·마감 확인
- [ ] 결과 창: 막대·포스트잇·표, 이름 토글, 청중 화면 띄우기
- [ ] CSV가 엑셀에서 한글 깨짐 없이 열림
- [ ] 방을 닫으면 답도 지워짐

## 6. 2단계 — 슬라이드 꾸미기 (글·도형·수식)

### 6.1 교사: 활동 장 지정
- 질문 창 유형에 **[꾸미기]**(`type: 'canvas'`)를 더합니다. 쓸 수 있는 도구를 고릅니다: ☑ 글 ☑ 도형 ☑ 수식.
- 열기·마감·[결과] 창은 1단계와 같습니다. [결과] 창이 **[학생 화면 모아 보기]**가 됩니다.

### 6.2 학생: 꾸미기 (태블릿·PC만, A5)
- **기기 판정**: 화면의 짧은 변(`Math.min(screen.width, screen.height)`)이 **600px 이상**이면 편집할 수 있습니다. 창 너비로 판정하면 가로로 돌린 휴대폰이 통과하므로 쓰지 않습니다. 휴대폰 리모컨(D36)과 달리 **아이패드는 편집 가능** 쪽입니다.
- 휴대폰: "태블릿이나 컴퓨터에서 꾸밀 수 있어요" 안내와 함께 보기만 합니다.
- 화면 판정은 학생 기기에서 하는 검사라 우회될 수 있습니다. 실제로 막는 것은 규칙의 크기 상한(4.2)입니다.
- 원래 장은 **잠긴 배경**이고, 학생 개체만 그 위에 얹습니다.
- 도구: 글 상자, 도형(사각형·원·선·화살표), 수식(`MathEditor` 축소판), 색, 지우기, 되돌리기.
- 터치 우선: 큰 손잡이, 끌어 옮기기, 두 손가락은 화면 확대.
- 저장: 바뀌고 2~3초 뒤 자동 저장(학생 개체 전체를 한 번에 덮어씀). "저장됨 ✓" 표시.
- **가장 큰 작업입니다.** `DirectInsert`·`MathEditor`를 최대한 다시 쓰되, PC 편집기(`Editor`)와 분리된 **작은 터치용 편집기**로 만듭니다(`Editor`는 덱·IndexedDB·되돌리기와 묶여 있어 그대로 쓰기 어려움).

### 6.3 데이터
```js
// live_answers/{code}/{askId}/{uid}.items — JSON 글 하나(20000자 이하)
[
  { "k": "text",  "x": 120, "y": 80, "w": 300, "h": 60, "text": "꼭짓점", "color": "#dc2626", "size": 32 },
  { "k": "arrow", "x": 200, "y": 150, "w": 120, "h": 0, "color": "#2563eb" },
  { "k": "math",  "x": 500, "y": 300, "w": 200, "h": 80, "tex": "y=(x-1)^2", "color": "#000000" }
]
```
- 좌표는 슬라이드 기준(0~1920 × 0~1080). 개체 최대 40개.
- `k`는 정해진 종류만, 색은 `#rrggbb`만, 숫자는 범위 안만 받습니다. 교사 PC가 **직접 그립니다**(HTML을 받지 않음, A6).
- 수식은 MathJax에 넣기 전에 위험한 명령(`\href`, `\html…`, `\require`, `\class`, `\style` 등)을 막습니다.

### 6.4 교사: [학생 화면 모아 보기]
- 이름이 붙은 **격자 썸네일**. 누르면 크게, ★ 고르기, [청중 화면에 띄우기](이름 숨김).
- 30개를 그대로 다 그리면 교사 PC가 느려집니다. **원래 장은 한 번만 그려 배경 그림으로** 쓰고 그 위에 학생 개체만 얹습니다. 인터랙티브 요소·모션그래픽은 멈춘 그림으로 보입니다.
- 학생이 저장할 때마다 그 학생 썸네일만 다시 그립니다.

### 6.5 사용량
- 학생 1명 개체 10개 ≈ 3KB, 수업 중 30번 저장 → 교사가 받는 양 **약 3MB/수업**.

### 6.6 2단계 끝 기준
- [ ] 태블릿·PC에서 꾸미기, 휴대폰은 보기만
- [ ] 30명 모아 보기가 느려지지 않음
- [ ] 조작된 `items`(이상한 종류·긴 글·스크립트)가 와도 교사 PC에서 그냥 무시됨

## 7. 3단계 — 사진

- 꾸미기에 **[사진]** 도구를 더합니다(태블릿·PC만).
- 학생 기기에서 **긴 변 1280px, JPEG 0.8로 줄인 뒤**(보통 100~300KB) Storage `live_work/{code}/{uid}/{id}.jpg`에 올리고, `items`에는 경로만 적습니다. 태블릿 카메라 사진(3~5MB)이나 PC의 큰 그림 파일도 이렇게 줄어듭니다.
- 학생 1명 사진 최대 3장(앱에서 막음).
- Storage 규칙(초안):
  ```
  match /live_work/{code}/{uid}/{file} {
    allow create: if request.auth != null && request.auth.uid == uid
                  && request.resource.size < 500 * 1024
                  && request.resource.contentType == 'image/jpeg'
                  && firestore.exists(/databases/(default)/documents/motionslide_live_records/$(code));
    allow get:    if request.auth != null && (request.auth.uid == uid || isAdmin()
                  || firestore.get(/databases/(default)/documents/motionslide_live_records/$(code)).data.createdBy == request.auth.uid);
    allow delete: if request.auth != null && (request.auth.uid == uid || isAdmin()
                  || firestore.get(/databases/(default)/documents/motionslide_live_records/$(code)).data.createdBy == request.auth.uid);
  }
  ```
- 교사 모아 보기: 30명 × 2장 × 200KB = **약 12MB/수업**.
- 부적절한 사진: 학생끼리 보지 않고(A1), 청중 화면에는 교사가 고른 것만 띄웁니다. 교사 창에서 [숨기기].
- 방을 닫을 때 `live_work/{code}/` 폴더도 지웁니다(4.3).

## 8. 보안 정리

| 위험 | 막는 법 | 단계 |
|---|---|---|
| 방 코드만 아는 사람이 남의 답을 덮어씀 | 익명 uid 경로 규칙(자기 칸만) | 0 |
| 큰 데이터를 반복해서 보냄 | 규칙의 글자 수·크기 상한, 마감되면 쓰기 거부 | 0·3 |
| 익명 학생이 교사 기능에 접근 | 기존 규칙의 `auth != null` 전수 점검 | 0 |
| 익명 학생에게 교사 등록 창이 뜸 | `teacher-auth.js`에서 `isAnonymous` 처리 | 0 |
| 학생 글·작품으로 교사 PC를 공격 | HTML을 받지 않음, 글자로만 넣기, 수식 명령 제한, `items` 검사 | 1·2 |
| 정답을 미리 봄 | 학생용 덱에서 정답 칸을 뺌 | 1 |
| 부적절한 내용이 반 전체에 보임 | 학생끼리 못 봄, 청중 화면은 교사가 고른 것만, 이름 숨김 기본 | 1~3 |
| 학생 기록이 오래 남음 | 방을 닫을 때 답·사진을 함께 지움, CSV 저장 안내 | 0 |
