## 0. 한눈에 보기 — 일이 진행되는 순서

```
0단계  기반 공사 ─────────── 화면에는 거의 안 보임. 1·2단계가 모두 이 위에 올라감
  │    학생 쓰기 규칙(RTDB, 로그인 없음·제출 열쇠) · 방 닫을 때 학생 답도 함께 지우기
  ▼
1단계  의견 모으기 ───────── 먼저 수업에서 써 보고 다음으로
  │    교사: 장에 질문 붙이기 → 학생: 답하기(모든 기기) → 교사: 결과 보기 → 장으로 넣기
  ▼
2단계  학생 슬라이드 보기 ──── 교사가 학생 각자의 슬라이드를 확인 (인터랙티브 조작 결과 + 붙인 글 + 판서)
       교사: 장에 [학생 슬라이드] 질문을 붙임 → 그 장에서만 학생 화면에 도구가 생김
       학생: 인터랙티브 요소 조작 · 글상자 · 판서(휴대폰 포함) → 제출
       교사: 학생별 "원래 장 + 요소 상태 + 붙인 글 + 판서"를 모아 보기
```

| 단계 | 교사가 하는 일                                                                             | 학생이 하는 일                                                       | 다음 단계로 가는 기준                                                                           | 작업량 |
| ---- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------ |
| 0    | RTDB 규칙 배포                                                                             | (변화 없음)                                                          | 학생 기기가 열린 질문에만 쓸 수 있고 남이 낸 답은 덮어쓸 수 없음, 기존 게임·설문이 그대로 동작 | 작음   |
| 1    | 편집기에서 질문 붙이기, 발표 중 [결과] | 휴대폰·태블릿·PC에서 답하기·고치기 | 실제 수업 1회에서 답하기·자동 열림/닫힘·장으로 넣기·방 닫기까지 문제없음 | 중간 |
| 2    | 장에 [학생 슬라이드] 질문 붙이기(글상자·판서 켜기), [결과]에서 학생 슬라이드 모아 보기 | 그 장에서만: 인터랙티브 요소 조작, 글상자·판서(휴대폰 포함), 제출 | 실제 수업 1회, 30명 모아 보기가 느리지 않음                                                     | 중간   |

- 각 단계는 **실제 수업에서 한 번 써 본 뒤** 다음 단계로 갑니다. 써 보고 필요 없으면 거기서 멈춰도 됩니다.
- 1단계까지만 해도 수업에서 쓸 수 있는 완성된 기능입니다.
- 처음 계획의 **슬라이드 꾸미기(학생용 개체 편집기)는 뺐습니다**(A10). 핵심이었던 **교사가 학생 슬라이드를 보는 것**(인터랙티브 조작 결과와 부연 설명 포함)은 2단계가 훨씬 작은 작업으로 해결합니다.

## 3. 전체 구조

```
 [교사 PC: 편집기]
   장 ⋯ 메뉴 / 직접 삽입 → [질문 붙이기] → slide.ask (덱에 저장)

 [교사 PC: 함께 보기 시작]
   LiveDeck.build → 학생용 덱에 질문 포함 → Storage (기존과 같음)

 [교사 PC: 발표자 모드]
   질문 장에 옴              ──► RTDB live/{code}/asks/{askId} = 'open'
   다른 장으로 감·발표 끝    ──► RTDB live/{code}/asks/{askId} = 'closed'   (A16)
   발표자 바 [❓ 12/27] · [결과] 창 ◄── RTDB live_answers/{code}/{askId}/*   (교사만 읽음)
   [청중 화면에 띄우기] → 청중 화면에 결과(이름 숨김)

 [학생 기기] ── 로그인 없음. 빠른 입장: 자동 닉네임 / 학번 인증: 학번 ──
   받아 둔 덱의 질문 + live/{code}/asks 구독 → 열린 질문이면 답 칸
   [제출] / [수정]  ──► RTDB live_answers/{code}/{askId}/{닉네임 또는 학번}
                        (제출 열쇠가 맞을 때만 고침. 학생 슬라이드의 사본·판서도 이 칸에 글로)
```

- 진행 신호·일시정지·보기 모드는 기존 함께 보기 그대로입니다. 질문은 그 위에 **`asks`(열림/닫힘)와 `live_answers`(학생 답)** 두 칸만 더합니다. Storage는 쓰지 않습니다(4.2).
- 2단계 학생 슬라이드 보기도 **질문 유형 하나(`slide`)**로 넣어 같은 열고 닫기·결과 창을 씁니다.
- 일시정지(⏸) 중에는 질문이 열린 채로 덮개가 답 칸을 가립니다(A16).

## 4. 0단계 — 기반 공사

### 4.1 학생 구분 — 로그인 없음 (A7)

- 학생은 **Firebase 로그인을 하지 않습니다**(기존 함께 보기·게임과 같음). 입장 창(`renderRoomEntrance`)이 정한 정보로 구분합니다.

| 입장 방식 | 답 칸 이름(`{key}`) | 교사 화면에 보이는 이름     |
| --------- | --------------------- | --------------------------- |
| 빠른 입장 | 자동 닉네임           | 닉네임                      |
| 학번 인증 | 학번                  | 학번(닉네임은 함께 적어 둠) |

- 학번 인증 방에서는 같은 학번이면 다른 기기로 들어와도 같은 학생 칸입니다.
- 닉네임에 RTDB 키로 못 쓰는 글자(`. # $ [ ] /`)가 있으면 바꿔서 씁니다.
- **덮어쓰기 막기(제출 열쇠)**: 첫 제출 때 학생 기기가 무작위 열쇠(`token`, 24자 이상)를 만들어 답과 함께 저장하고 기기(localStorage)에 기억합니다. 고칠 때는 같은 열쇠가 있어야 합니다. 학생은 답을 읽을 수 없으므로 남의 열쇠를 알 수 없고, **이미 낸 남의 답을 덮어쓰거나 지울 수 없습니다.**
- **학생은 서버의 답을 읽지 않습니다.** 내가 낸 답은 기기에 남긴 사본으로 보여 줍니다(새로고침해도 유지).
- **한계(로그인이 없어서)**
  - 규칙은 "그 학번·닉네임이 정말 그 학생인지" 확인하지 못합니다. 남의 학번으로 **먼저** 제출하는 장난은 막지 못합니다. 기존 게임의 의견 포스트잇과 같은 수준입니다.
  - 기기·브라우저를 바꾸면 열쇠가 없어 처음 낸 답을 고칠 수 없습니다.
  - 두 경우 모두 교사가 결과 창에서 **[답 지우기]**를 누르면 그 칸이 비어 다시 제출할 수 있습니다.
- 익명 로그인을 쓰지 않으므로 `js/teacher-auth.js`와 기존 규칙은 고칠 것이 없습니다.

### 4.2 학생 쓰기 규칙 (RTDB 전용 인스턴스 `motionslide-live`에 추가)

```json
"live": {
  "$code": {
    "asks": { ".read": true, "$askId": { ".validate": "newData.val() === 'open' || newData.val() === 'closed'" } }
  }
},
"live_answers": {
  "$code": {
    ".read":  "auth != null && (auth.uid === '<ADMIN_UID>' || root.child('live').child($code).child('createdBy').val() === auth.uid)",
    ".write": "auth != null && (auth.uid === '<ADMIN_UID>' || root.child('live').child($code).child('createdBy').val() === auth.uid)",
    "$askId": {
      "$key": {
        ".write": "root.child('live').child($code).child('asks').child($askId).val() === 'open' && newData.exists() && (!data.exists() || data.child('token').val() === newData.child('token').val())",
        ".validate": "newData.hasChildren(['token', 'nick', 'at']) && $key.length <= 30 && (newData.child('nick').val() === $key || newData.child('sid').val() === $key)",
        "token":  { ".validate": "newData.isString() && newData.val().length >= 24 && newData.val().length <= 64" },
        "nick":   { ".validate": "newData.isString() && newData.val().length <= 30" },
        "sid":    { ".validate": "newData.isString() && newData.val().length <= 10" },
        "choice": { ".validate": "newData.hasChildren()", "$i": { ".validate": "newData.isNumber() && newData.val() >= 0 && newData.val() < 10" } },
        "reason": { ".validate": "newData.isString() && newData.val().length <= 500" },
        "text":   { ".validate": "newData.isString() && newData.val().length <= 2000" },
        "photo":  { ".validate": "newData.isString() && newData.val().beginsWith('data:image/jpeg;base64,') && newData.val().length <= 400000" },
        "notes":  { ".validate": "newData.isString() && newData.val().length <= 4000" },
        "snap":   { ".validate": "newData.isString() && newData.val().length <= 1500000" },
        "pen":    { ".validate": "newData.isString() && newData.val().beginsWith('data:image/png;base64,') && newData.val().length <= 300000" },
        "at":     { ".validate": "newData.val() === now" },
        "$other": { ".validate": false }
      }
    }
  }
}
```

- `live`의 `asks`는 기존 `live/$code` 규칙 안에 더합니다(교사 쓰기는 기존 규칙이 허락).
- 학생 쓰기 조건: **그 질문이 열려 있고**, 칸이 비었거나 **같은 열쇠**일 때만. 질문이 닫히면(교사가 다른 장으로 가면) 거부되고, 학생은 지울 수 없습니다.
- 칸 이름은 그 답의 닉네임(빠른 입장) 또는 학번(학번 인증)과 같아야 합니다.
- 교사(방 주인)와 관리자는 그 방의 답을 모두 읽고 지웁니다([답 지우기]·방 닫기).
- 글자 수 상한으로 큰 데이터를 반복해서 보내는 일을 막습니다. `notes`(2단계 글상자)는 **JSON 글 하나**로 받아 길이로 크기를 제한합니다(RTDB 규칙은 자식 개수를 셀 수 없어서). `photo`(장문형 사진)는 JPEG data URL 40만 자 이하만 받습니다.
- **Storage는 쓰지 않습니다.** 인터랙티브 요소 사본(`snap`, JSON 글)과 판서(`pen`, PNG data URL)도 답 칸에 글로 넣습니다.
  - 로그인 없이 Storage에 쓰게 하면 규칙으로 막을 수 있는 것이 크기·이름뿐입니다.
  - 답이 한 칸에 모여 있어 방을 닫을 때 `live_answers/{code}` 하나만 지우면 됩니다.

### 4.3 정리

- 학생 답 `live_answers/{code}`는 **방(`live/{code}`)을 지우기 전에 먼저** 지웁니다. 규칙이 `live/{code}`의 주인을 확인하기 때문입니다. `Live.cancel`(Storage 관리의 [함께 보기 취소]·덱 삭제)과 `js/teacher-cleanup.js`(계정 삭제·탈퇴)가 이 순서로 지웁니다. 규칙을 아직 넣지 않아 실패해도 방 정리는 계속합니다. (`room_registry`의 `parts`에는 더하지 않습니다. 방을 지운 뒤에는 주인 확인이 안 되기 때문입니다.)
- 방 닫기 확인 창: "학생 답 N개(학생 슬라이드 포함)도 함께 지워집니다."
  - 아직 장으로 넣지 않은 질문이 있으면: "결과를 장으로 넣지 않은 질문이 2개 있습니다. **[장으로 넣고 닫기] [그냥 닫기]**"

### 4.4 0단계 끝 기준

- [ ] 학생 기기(로그인 없음): 열린 질문에 제출·수정 성공, 닫힌 질문 거부
- [ ] **다른 열쇠로 남의 답 덮어쓰기·지우기 거부**, 학생은 답 읽기 거부
- [ ] 칸 이름과 닉네임·학번이 다르거나 너무 큰 답은 거부
- [ ] 교사 [답 지우기] 뒤 그 학생이 다시 제출 가능
- [ ] 기존 게임·설문·학생 관리가 그대로 동작

## 5. 1단계 — 의견 모으기

### 5.1 교사: 질문 붙이기 (편집기)

- 썸네일 ⋯ 메뉴(`SlideMenu`)와 직접 삽입 메뉴(`DirectInsert`)에 **[질문 붙이기]** → 질문 창(모달, `MathEditor`와 같은 방식).
- 한 장에 질문 하나. 질문이 있는 장은 썸네일에 **❓** 표시.

```
┌ 질문 붙이기 ──────────────────────────────────┐
│ 유형  (● 객관식) (○ 장문형) (○ 학생 슬라이드)         │
│ 질문  [ 이 포물선이 아래로 볼록한 이유는?           ]  │
│ ── 객관식 ──                                       │
│ 보기  ① [a > 0]   ② [a < 0]   ③ [      ]  [+ 보기]  │
│ ☐ 여러 개 고르기      이유  (○ 없음)(● 선택)(○ 필수)  │
│ ── 장문형 ──                                       │
│ 글자 수 제한  [500]   ☑ 학생 사진 넣기               │
│ ── 학생 슬라이드 (6장) ──                            │
│ (질문 글은 비워도 됨 · 글상자·판서는 늘 켜짐)          │
│                              [질문 지우기] [취소] [저장] │
└───────────────────────────────────────────┘
```

**데이터 (덱 안, 장마다)**

```js
slide.ask = {
  // 답을 묶는 키는 장 id(slide.id) — 장을 복제하면 새 id라 답이 섞이지 않는다
  type: 'choice' | 'long' | 'slide',
  text: '질문 글',
  choices: ['a > 0', 'a < 0'],                        // 객관식, 최대 10개
  multi: false,                                       // 여러 개 고르기
  reason: 'none' | 'optional' | 'required',           // 객관식 이유(학생 슬라이드는 늘 'none' — 장 위 글상자로 설명)
  notes: true,                                        // 학생 슬라이드: 글상자 도구
  pen: true,                                          // 학생 슬라이드: 판서 도구
  max: 500,                                           // 장문형 글자 수 제한(최대 2000)
  photo: true                                         // 장문형: 학생 사진 1장
}
```

- `Editor.normalizeSlide`가 `ask`를 정리(모르는 칸 버림, 길이 제한)합니다. 되돌리기 기록은 덱 전체를 저장하므로 질문도 자동으로 되돌려집니다.
- 슬라이드 화면에는 질문이 자동으로 그려지지 않습니다. 학생 답 칸 위에 질문 글이 보입니다. 슬라이드에도 보이게 하려면 교사가 글 상자로 적습니다.
- 내보낸 HTML(오프라인)에서는 질문이 무시됩니다.

### 5.2 학생: 답하기 (모든 기기)

```
 휴대폰                              태블릿·PC
┌──────────────┐               ┌──────────────────────┬──────────┐
│  (슬라이드)    │               │                      │ ❓ 질문   │
│              │               │     (슬라이드)         │ 보기 ①②③ │
├──────────────┤               │                      │ 이유 [  ] │
│ ❓ 질문        │ ← 아래에서     │                      │ [제출]    │
│ ① a>0  ② a<0  │   올라오는 판   └──────────────────────┴──────────┘
│ 이유 [       ]│
│     [제출]    │
└──────────────┘
```

- 실시간 페이지에서 질문 장이 열리면(`asks/{id} == 'open'`) 답 칸이 뜹니다.
- **객관식**: 보기 단추 → (설정에 따라) 이유 칸 → [제출]. 질문이 열려 있는 동안은 [수정]으로 바뀝니다.
- **장문형**: 글 칸(남은 글자 수 표시) + **[📷 사진 넣기]**(교사가 켠 질문, 카메라·사진첩) → [제출]. 글이나 사진 중 하나는 있어야 합니다(A4).
  - 교사 결과 창: 포스트잇·표에 사진이 보이고, 누르면 크게 봅니다. 발표 중이면 크게 보기의 [청중 화면에 띄우기]로 그 답 하나를 크게 띄웁니다(이름 숨김).
  - [장으로 넣기]: 글만 낸 답은 포스트잇 장, 사진이 있는 답은 한 장씩(왼쪽 사진, 오른쪽 글).
- 교사가 다른 장으로 넘어가면 질문이 닫혀 "닫혔어요"와 내 답만 보입니다. 교사가 그 장으로 돌아오면 다시 열려 이어서 고칠 수 있습니다(A16). 넘어가는 순간에 낸 답이 거부되면 "질문이 닫혀 제출하지 못했어요"라고 알리고 쓴 글은 남겨 둡니다.
- 제출 전에 쓰던 글과 **제출한 답**은 기기에 남겨 둡니다(새로고침해도 유지). 학생은 서버의 답을 읽지 않으므로 "내 답"은 이 사본으로 보여 줍니다(4.1).
- 처음 낸 기기가 아니면(열쇠가 없으면) 고치기가 거부됩니다. 이때 "선생님께 답 지우기를 부탁하세요"라고 안내합니다.
- 일시정지(⏸) 중에는 덮개가 답 칸도 가립니다. 쓰던 글은 그대로 남습니다.
- 학생 글은 화면에 **글자로만** 넣습니다(`textContent`, HTML로 넣지 않음).

### 5.3 교사: 결과 보기

- 발표자 모드에서 질문 장에 오면 질문이 열리고(학생 화면의 질문 단추가 눌림), 발표자 바에 **[❓ 응답 12/27 · 결과]**가 보입니다. 다른 장으로 가면 닫힙니다(A16).
- **[결과]** → 별도 창(청중 화면처럼). 한 화면 교실은 Q6.

| 유형   | 결과 화면                                                                                                                                                                                                 |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 객관식 | **보기별로 묶은 이유 포스트잇**, 묶음 머리에 인원 수(`① a > 0 — 12명`). 같은 답을 고른 학생들의 이유를 비교해 오개념을 찾기 좋음. 막대그래프는 두지 않음(A14) |
| 장문형 | **포스트잇 ↔ 표** 전환. 포스트잇을 누르면 크게. ★로 골라 두기                                                                                                                                     |

- **[이름 보기]** 토글(빠른 입장: 닉네임, 학번 인증: 학번): 교사 창에서는 켜짐이 기본. **[청중 화면에 띄우기]** 하면 이름은 꺼진 채로 띄웁니다(A8). 결과 전체 또는 ★ 고른 것만 띄울 수 있습니다.
- **[답 지우기]**: 학생 답 하나를 지웁니다. 남의 학번으로 먼저 낸 장난이나 기기를 바꿔 못 고치는 학생을 풀어 줄 때 씁니다(4.1). 지우면 그 학생이 다시 제출할 수 있습니다.
- **표 보기**(A20): 칸은 이름 · (객관식) 고른 보기·이유 / (장문형) 답 / (학생 슬라이드) 제출한 것·설명 · 시각 · ★·숨기기·답 지우기(학생 슬라이드는 크게 보기도). 서식만 대시보드형입니다(얇은 테두리 흰 카드, 회색 작은 머리글, 가로 구분선, 줄 호버, 고른 보기 칩, 둥근 아이콘 단추). 이름 보기를 끄면 이름 칸이 빈칸이 됩니다.
- 교사는 **지금 질문의 `live_answers/{code}/{askId}`만 구독**합니다. 학생이 제출·수정할 때 그 학생 칸만 받습니다.
- **다시 쓸 코드**: [relativefrequency.html](../../middleschool/1/relativefrequency.html)의 의견 포스트잇·학생 현황표·학번 칩 토글.

#### 결과를 장으로 넣기 (A13)

결과 창의 **[장으로 넣기]**는 결과를 **보통 슬라이드**로 만들어 질문 장 바로 뒤에 넣습니다. 한 번 장이 되면 내보내기(HTML·PDF)·발표·편집이 모두 지금 기능 그대로 됩니다.

| 유형           | 만들어지는 장                                                                  |
| -------------- | ------------------------------------------------------------------------------ |
| 객관식         | 보기별 묶음(인원 수 + 이유 포스트잇) 장. 많으면 여러 장으로 나눔               |
| 장문형 | 포스트잇 장(한 장에 6개씩 여러 장). 사진이 있는 답은 한 장씩(사진 + 글)         |
| 학생 슬라이드  | 학생마다 원래 장을 복제하고, 요소 자리에 그 학생 사본, 글상자는 같은 자리·서식으로(6.4) |

- **넣을 범위**: 전체 또는 ★ 고른 것만. 학생 슬라이드는 학생 수만큼 장이 생기므로 ★만 권합니다.
- **이름**: 숨김이 기본. 넣을 때 [이름 표시]를 고르면 붙습니다. 덱은 공유하거나 다음 수업에서 학생에게 다시 보일 수 있기 때문입니다.
- 만든 장은 보통 글상자·그림·인터랙티브 요소로만 이루어집니다. 학생 글은 글상자에 글자로만 넣습니다.
- 결과 장에는 표시(`slide.result = { askId, at }`)를 붙입니다. 썸네일 ⋯ 메뉴의 **[결과 장 지우기]**로 모아 지울 수 있습니다. 덱을 다시 함께 보기로 열면 결과 장도 학생에게 가므로, 원하지 않으면 지웁니다.
- 덱 크기: 글 결과는 작습니다. 학생 슬라이드(인터랙티브 사본)를 많이 넣으면 질문 하나에 몇 MB가 될 수 있어, 덱이 30MB 제한에 가까워지면 넣기 전에 알립니다.
- 학생 답 원본은 서버(함께 보기 방)에만 있고, 방을 닫으면 지워집니다. 남길 것은 [장으로 넣기]로 옮깁니다.

### 5.4 데이터 구조 (RTDB)

```
live/{code}/asks/{askId}: 'open' | 'closed'          // 교사만 씀, 학생은 읽기
live_answers/{code}/{askId}/{key}: {                 // key: 빠른 입장 = 닉네임, 학번 인증 = 학번
  token:  '무작위 24자 이상',                           // 제출 열쇠(첫 제출 기기만 고침, 4.1)
  nick:   '빨간 여우',                                 // 자동 닉네임(두 방식 모두)
  sid:    '30312',                                    // 학번 인증 방만
  choice: [1],                                        // 객관식
  reason: '…',                                        // 500자 이하
  text:   '…',                                        // 장문형(설정값, 최대 2000자)
  at:     서버 시각
}
```

### 5.5 사용량 (학생 30명, 질문 5개, 1회씩 고침)

## 6. 2단계 — 학생 슬라이드 보기

**핵심: 교사가 학생 각자의 슬라이드를 봅니다.** 학생 슬라이드에는 그 학생이 인터랙티브 요소를 조작한 결과, 슬라이드에 붙인 글(부연 설명), 판서가 담깁니다. 교사는 학생별 슬라이드 전체를 모아 봅니다.

### 6.1 교사: 질문 붙이기

- 질문 창 유형 **[학생 슬라이드]**(`type: 'slide'`). 어느 장에나 붙일 수 있습니다.
- 설정이 없습니다: 질문 글은 비워도 되고(학생 화면에는 "내 슬라이드 활동"), 글상자·판서는 늘 켜져 있습니다. 설명 칸도 없습니다(학생은 장 위 글상자로 설명).
- 열고 닫는 방식(A16)·[결과] 창은 1단계와 같습니다. 편집기 썸네일에는 ❓ 표시가 붙습니다.
- **편집기 질문 단추**: 질문이 붙은 장을 열면 슬라이드 오른쪽 아래에 학생 화면과 같은 보라색 알약 단추(`❓ 객관식 · 질문…`, `✏️ 내 슬라이드 활동`)가 보입니다. **더블클릭하면 질문 창**이 열립니다. 장 HTML이 아니라 편집기 화면에만 띄우므로 발표·내보내기·학생 화면·축소판에는 나오지 않습니다.
- **질문 기능은 승인 교사·관리자만**: [질문 붙이기·고치기]·[질문 결과 보기](장 ⋯ 메뉴), 직접 삽입의 [질문 붙이기], 편집기 질문 단추·축소판 ❓는 승인된 선생님이나 관리자로 로그인했을 때만 보입니다(함께 보기를 열 수 있는 사람과 같음). 로그인 상태가 바뀌면 바로 다시 맞춥니다. 다른 사람이 질문을 붙인 덱을 받아도 질문 데이터는 덱에 그대로 남습니다.
- **내보내기·불러오기**: 질문(`slide.ask`)은 덱 데이터이므로 단추와 상관없이 남습니다. **[발표자 보기] 파일**은 질문·결과 장 표시를 담아 다시 불러오면 질문과 단추가 그대로 돌아옵니다. **[청중 화면만] 파일**은 시나리오처럼 질문을 빼고 내보내므로 다시 불러오면 질문이 없습니다. 클라우드 저장도 질문을 그대로 둡니다.

### 6.2 학생: 조작·글상자·판서 → 제출

- **도구가 나타나는 때(A15·A16)**: 학생 화면의 **[✏️ 내 슬라이드 활동]** 단추는 질문이 열려 있을 때만 눌립니다. 누르면 오른쪽 입력창 없이 **장 위에 활동 막대**가 뜹니다: 질문 글 · [🔤 글상자] [✏️ 판서] · [제출] [✕]. 막대는 ⠿를 끌어 옮길 수 있습니다(자리는 기기에 남김).
  - 막대가 떠 있는 동안 글상자를 누르면 고르고 고칠 수 있고, 그 밖의 자리는 인터랙티브 요소 조작입니다. [판서]를 켠 동안에만 판서 층이 눌림을 받습니다.
  - 막대 아랫줄: 판서를 켜면 펜 도구, 글상자를 고르면 서식(굵게·기울임·밑줄·크기·정렬·색·지우기).
  - 글상자·판서는 막대를 닫아도 장 위에 남아 보입니다.
  - 다른 장: 도구가 없고 보기만 합니다.
  - 교사가 다른 장으로 넘어가면 질문이 닫혀 도구가 사라지고, 내가 제출한 모습만 보입니다. 교사가 그 장으로 돌아오면 다시 열려 이어서 고칠 수 있습니다.

```
1. (인터랙티브 요소가 있으면) 조작한다 — 슬라이더 움직이기, 점 끌기 등
2. [글상자] → 장 가운데에 글상자가 생긴다 → 그 자리에서 바로 글을 쓴다 → 서식·색을 고른다
   ✥로 끌어 옮기고, ↔로 너비를 바꾸고, × 로 지운다
3. [판서] → 펜·형광펜·지우개로 장 위에 그린다 (7장)
4. [제출] → 요소 사본 + 글상자 + 판서가 함께 간다. 질문이 열려 있는 동안 [다시 제출]로 덮어쓴다
```

- **요소 사본**: [제출]을 누르면 학생 기기가 그 장의 인터랙티브 요소마다 사본을 요청합니다. 요소 안의 도우미(`appBridge`)가 PDF 내보내기용으로 이미 가진 기능(`lsApp: 'snapshot'`)을 그대로 씁니다.
  - 결과는 지금 상태 그대로의 **정적 HTML**입니다. 캔버스(Chart.js·p5 등)는 그림으로 바뀌고, 슬라이더·입력칸 값과 끌어 옮긴 점(SVG)은 그 자리 그대로 남고, 스크립트는 빠지고, 움직임은 끝난 모습으로 멈춥니다.
  - 요소가 여러 개면 요소 아이디(`data-app`)별로 묶어 `snap`(JSON 글) 하나로 답에 넣습니다.
  - 2초 안에 사본을 보내지 않는 요소는 빈 사본으로 두고, 교사 창에 "사본 없음"으로 보입니다.
  - **3D(three.js)**: 그리는 방식 때문에 사본 캔버스가 빈칸일 수 있습니다. 렌더러에 `preserveDrawingBuffer: true`를 쓰도록 AI 지시문에 한 줄 더합니다(9장).
- **글상자**
  - 자리는 슬라이드 좌표(0~1920 × 0~1080)로 저장합니다. 학생 기기 화면 크기와 상관없이 교사 화면의 같은 자리에 붙습니다.
  - 최대 10개, 각 200자. 서식은 글상자 전체에 하나: 굵게·기울임·밑줄, 글자 크기(20~120px), 정렬(왼쪽·가운데·오른쪽), 색(8색 + 고르기). 바탕·테두리는 없습니다(교사 글상자처럼). 새 글상자는 마지막에 고른 서식을 따릅니다. 글자로만 넣습니다(`textContent`).
  - 손잡이(옮기기·지우기·너비)는 글상자 바깥 모서리에, 배율과 관계없이 화면에서 34px로 보입니다(`--live-inv`).
- **휴대폰**: 모든 도구를 씁니다(A5). 장이 작으므로 가로로 돌리거나 두 손가락으로 확대해서 쓰면 편합니다.

### 6.3 데이터

```
live_answers/{code}/{askId}/{key}: {                   // key: 닉네임 또는 학번(4.1)
  token, nick, sid,
  reason: '설명 글',                                    // 500자 이하
  notes:  '[{"x":820,"y":410,"w":520,"t":"이 점이 꼭짓점","s":40,"c":"#dc2626","b":1,"i":0,"u":0,"a":"l"}]', // 글상자 JSON 글 하나, 4000자 이하
  snap:   '{"frames":[{"id":"app1a2b3c","html":"<!DOCTYPE html>…"}]}',  // 인터랙티브 요소가 있을 때, 150만 자 이하
  pen:    'data:image/png;base64,…',                   // 판서했을 때, 30만 자 이하
  at:     서버 시각
}
```

- 사본·판서도 Storage가 아니라 **답 칸에 글로** 넣습니다(4.2).
- 교사 PC는 `notes`를 읽을 때 다시 검사합니다: 숫자 범위, 글 길이, 개수. 색은 `#rrggbb`, 정렬은 l·c·r만 받고, 어긋나면 기본값으로 고치거나 그 글상자만 버립니다.

### 6.4 교사: [결과] — 학생 슬라이드 모아 보기

- **원리(A11)**: 교사가 가진 **원래 장**을 그리고, 인터랙티브 요소 자리(`data-app`이 같은 칸)에 **그 학생의 사본**을 끼우고, 그 위에 **판서**와 **글상자**를 겹칩니다. 학생이 제출할 때 보던 슬라이드 전체가 됩니다. 슬라이드 자체는 보내지 않습니다.

```
┌ 학생 슬라이드 ─ 응답 24/27 ────────────────────────────┐
│ [김○○]        [이○○]        [박○○]        [최○○]         │
│ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐  │
│ │원래 장   │ │원래 장   │ │원래 장   │ │원래 장   │  │  ← 장 전체 축소판
│ │+ 요소상태│ │+ 요소상태│ │+ 요소상태│ │+ 요소상태│  │
│ │+ 글상자·판서│ │+ 글상자·판서│ │+ 글상자·판서│ │+ 글상자·판서│  │
│ └────────┘ └────────┘ └────────┘ └────────┘  │
│  ★ 설명 글…     ★ 설명 글…     …                         │
└───────────────────────────────────────────┘
```

- 편집기 썸네일(`Mini`)처럼 축소판으로 그립니다. 장은 정적 보기(모든 상자 보임, 움직임 끝난 모습)입니다.
- 누르면 크게, ★ 고르기, [청중 화면에 띄우기](이름 숨김), 설명 글은 축소판 아래에 보입니다.
- 학생이 다시 제출하면 그 학생 축소판만 다시 그립니다.
- **[장으로 넣기]**(A13): 고른 학생마다 원래 장을 복제합니다. 요소 자리(`.app-frame`)의 코드를 그 학생 사본으로 바꾸고, 판서는 장 전체 크기의 그림으로, 글상자는 같은 자리·서식의 글상자로 넣습니다(이름은 숨김이 기본). 학생 수만큼 장이 생기므로 ★ 고른 것만 넣기를 권합니다.

| 학생 기기 화면과 다른 점 | 교사 결과 창                                                                                                                |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 화면 틀                  | 휴대폰의 답 칸 같은 학생 화면 틀은 빼고, 표준 슬라이드 크기(1920×1080)로 보임. 모든 학생이 같은 크기·배치라 비교하기 쉬움 |
| 단계별 공개·움직임      | 모든 상자가 다 나타나고 움직임이 끝난 모습                                                                                  |
| 동영상                   | 재생 위치는 전해지지 않고 첫 화면                                                                                           |
| 요소 안의 스크롤         | 맨 위로 돌아간 모습                                                                                                         |

### 6.5 사본 보안 (교사 PC)

사본은 학생 기기에서 오므로, **학생이 고쳐 보낼 수 있는 HTML**로 취급합니다.

- `sandbox=""` 칸(스크립트·양식·이동 없음)에만 넣습니다.
- 사본 맨 앞에 교사가 CSP를 붙입니다: `default-src 'none'; img-src data:; style-src 'unsafe-inline' (허용 CDN); font-src data: (허용 CDN)`. 사본 안에 다른 CSP가 있어도 규칙은 더 좁아지기만 합니다. 허용 CDN은 라이브러리 스타일·글꼴(JSXGraph·KaTeX 등)이 제 모양으로 보이게 하려는 것입니다.
- 넣기 전에 `<meta http-equiv>`·`<base>`·`<iframe>`·`<object>`·`<embed>`·`<script>`를 지웁니다.
- 사본은 답 칸의 글로만 오갑니다(Storage에 파일로 두지 않으므로 주소로 열어 실행될 일도 없음).
- 글상자·설명은 글자로만 넣습니다(글상자 서식은 검사한 숫자·색만 스타일에 넣음).
- **장으로 넣을 때**: 사본이 인터랙티브 요소 칸(스크립트가 도는 격리 칸)에 들어가므로, 넣기 전에 DOMPurify로 스크립트·`on…` 속성·위험한 태그를 지운 **정적 HTML**만 남깁니다. 격리 칸이라 이 페이지에는 닿지 못하지만, 다음 수업에서 학생 기기로도 가기 때문입니다.

### 6.6 사용량

- 사본: 학생 1명 보통 50~300KB(캔버스가 크면 더 큼, 상한 2MB) → 30명 **약 1.5~9MB/질문**. 제출·다시 제출할 때만 오갑니다.
- 글상자: 몇 KB. 장문형 사진: 한 장 300KB 안팎(40만 자 이하).

- 조작 과정을 실시간으로 지켜보기(A12)
- 결과 값 받기(Q7) — 써 보고 결정
- 학생용 개체 편집기(글상자·도형·수식 넣고 고치기, A10)

### 6.8 2단계 끝 기준

- [ ] 슬라이더·점 끌기(JSXGraph)·차트(Chart.js) 요소에서 조작한 상태가 교사 창에 그대로 보임
- [ ] 글상자가 학생 화면과 같은 자리·서식으로 보임(학생 기기 ↔ 교사 PC)
- [ ] 휴대폰: 조작·글상자·판서·제출 가능, 활동 막대가 화면 안에 들어옴
- [ ] [글상자]·[판서]는 질문이 붙은 장에서 열려 있는 동안만, 교사가 켠 것만 보임. 다른 장·닫힌 뒤에는 없음
- [ ] 판서가 학생 화면과 같은 자리에 겹쳐 보임

## 7. 판서 (2단계의 도구)

- 학생 슬라이드 질문에서 **☑ 판서**를 켠 장에서만, 질문이 열려 있는 동안 학생 화면에 **[판서]**가 나타납니다(A15, 휴대폰 포함).
- 학생 화면의 슬라이드 위에 투명 그림판(canvas, 슬라이드 좌표 1920×1080 기준)을 겹쳐 펜·형광펜·지우개로 그립니다. 색 몇 가지와 굵기 2~3단계, 되돌리기 한 단계.
- 판서 중에는 그림판이 터치를 받으므로 인터랙티브 요소를 조작할 수 없습니다. [판서]를 다시 누르면 꺼지고 요소를 조작할 수 있습니다.
- 제출하면 **판서 자국만** 투명 PNG(960×540으로 줄임, 보통 수십 KB)를 글(data URL)로 답 칸의 `pen`에 넣고, 교사 창에서 장 위에 겹칩니다. 그림판은 앱이 직접 그린 것이라 바로 그림 파일로 저장됩니다. 슬라이드를 그림으로 찍을 필요는 없습니다(A11).
- 판서도 학생 슬라이드의 일부로 교사 창과 [장으로 넣기]에 함께 보입니다.
- 사용량: 30명 × 50KB ≈ **1.5MB/질문**.
- 부적절한 그림: 학생끼리 보지 않고(A1), 청중 화면에는 교사가 고른 것만 띄웁니다. 교사 창에서 [숨기기].
